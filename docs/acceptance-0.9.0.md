## 查出并修复的问题

早期真实测试发现“按数量降序”被忽略，以及一般分工、已完成事项混入待办。现在数值排序实际执行，不支持的排序停止；文档先识别未完成/未来事项，再由本地模型选择段落。修复后独立测试和最终安装包都重新跑通，早期失败记录保留在本地，不覆盖为成功。

0.8.1的新隔离Codex会话无法完成系统配置同步，本版不依赖这条路径。默认流程改为本地计算/本地模型，不再要求第二次Agent登录、逐列设置、批准脱敏稿或确认导出。

## 隐私核验与边界

Mac处理进程及推理子进程被系统禁止联网，包含本机回环连接；未隔离进程在读取原件前拒绝运行。数据处理代码不开放任意执行接口，本地模型只返回实体片段和段落编号。下载安装固定组件在读取原件前完成，文件须匹配锁定SHA-256。

这证明本次处理流程保持本地，不证明宿主Agent、其他应用或整台电脑已受同一隔离约束。实体识别仍可能漏检；因中间稿也不上传，漏检不会导致本流程向云端发送正文。

文档当前只做提取式摘要/待办，不能作为任意改写器；样例正确不证明所有文档都能选对段落。表格不支持分组、复杂公式、任意新增列或自动提交系统。Windows离线虚拟机和WorkBuddy入口已经适配，仍无Windows实机验收；Intel Mac也未实测。

## 重现方法

先按[构建说明](development.md)生成完整包，从包内运行自动安装入口。使用任意新建的虚构CSV/XLSX或基础文档，执行安装目录中的：

```sh
python3 -B scripts/background.py submit --input /path/to/fictional-file --task '具体任务'
python3 -B scripts/background.py status --id returned-job-id
```

任务可直接采用机器可读记录中的请求。Windows使用包内runtime/python.exe，尚需实机确认。只有completed代表完成；queued、preparing_runtime和background_installation_started均不是成功验收。正式业务材料不得用普通读文件工具读取来核对测试。
