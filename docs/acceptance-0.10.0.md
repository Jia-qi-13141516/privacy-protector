# 0.10.0 首次性能自检验收

2026年10月25日；Apple M5、24GiB内存。材料全部虚构，不是8GB、Windows或Intel Mac实机验收。本版仍为本地验收包，未更新GitHub Release。

## 自动流程

首次准备组件后，在与业务任务相同的断网边界内检查：虚构表格筛选/排序/统计/新增列、零匹配导出、虚构DOCX待办提取、原件不变、导出身份和原值一致，以及真实模型调用。检查失败或未完成时不能读取业务文件。

合格结果与版本/文件清单、运行参数及基础硬件信息绑定，重复启动可复用。后续任务仍重新检查当前可用内存和断网边界；全局队列只允许一个处理任务运行。

## 已完成的独立使用验收

测试者使用独立目录，从安装入口开始操作，并自行构造新的业务样例，没有预先读取开发测试答案。

独立测试指出重复启动仍出现“首次自检”的过时文案，已改为“检查本机运行环境”。

## 资源与保护

同一短纪要选段，使用相同模型、8K上下文、断网策略和macOS `time -l`测量：

| 指标 | 0.9.0参数 | 0.10.0省内存参数 |
| --- | --- | --- |
| 推理进程峰值RSS | 2,269,315,072字节 | 1,526,398,976字节 |
| 该次推理耗时 | 2.530秒 | 2.935秒 |

峰值约下降32.7%，该样例速度略慢。结果不是整套程序或虚拟机的总内存，不代表长文档的完整耗时。调整为2线程、小批次并关闭额外权重重排副本，没有更换模型、降低量化精度、缩短上下文或放宽隔离。

模型进程采样RSS超过2GiB、单次推理超过120秒、监测不可用都会停止；首次短材料自检超过60秒提示较慢，超过180秒不通过。Windows代码另外设置客体自检超时终止。资源不足和自检失败只返回固定原因，不返回材料正文，不切换到云端。

151项检查通过，其中新增24项覆盖：8GB容量边界、当前可用内存不足、Windows主机/虚拟机内存分别检查、真实子进程超内存或超时终止、监测失败、旧记录不被误当合格、检查失败先于原件读取、并发串行和清晰错误状态。
