# 原件访问隔离：实现与验收

原件选入后，普通 Agent 的文件读取请求应由操作系统拒绝。只在 Skill 中要求“不读取”，或者把文件放进同一账号的隐藏目录，不能达到这一点。

开发入口已接入独立权限安装器与首次自检。一次性 Mac 测试机已通过真实服务安装、自检、表格和文档流程、服务重启验证；Windows 的真实文件权限、通信身份、后台服务安装与重启已通过，离线处理环境继续单独验收。桌面窗口、WorkBuddy 和 8GB 实体设备尚未完成验收，开发入口仍不向教师启用。公开的 0.10.0 安装包不具备这些新增的访问隔离保证。开发者的日常电脑没有部署或更新本组件。

## 工作方式

1. **说任务。** 原 Agent 只能提交任务文字、查询状态和打开本地结果窗口，不能提交原件路径、执行代码、读取正文或指定导出文件。
2. **选文件。** 独立权限的本地组件接收选中的文件。先记录恢复信息，再改变原件的文件所有权和访问权限，检查已有文件句柄，并以 Agent 的实际系统身份尝试读取、改权限和改所有者。检查通过后才读取原文。
3. **确认结果。** 原有表格和文档引擎在另一个处理账号下运行，网络受操作系统限制。原件副本、身份映射、处理临时文件和待确认结果均不属于 Agent 的可读范围。结果在本地窗口中核对，确认后才保存为普通文件。

选入的原件仍保留原位置与内容，但普通软件暂时不能直接打开。重复处理无需解锁。需要取回时，通过本地窗口明确恢复访问；原位置被改名或删除后，可从已经完整验证的快照另存副本。失败不会自动解锁原件，也不会转到云端。

**确认导出的结果和主动取回的原件副本是普通文件，其他软件可能读取。** 保护不追溯选入前已经复制、读取或上传的内容，也不覆盖系统管理员提权、屏幕录制或可操作界面的其他软件。因此，这里的“隔离”准确指普通 Agent 的直接文件访问和公开任务接口，不能写成对整台电脑的绝对保密保证。

## Linux 基础验证

验证使用两个独立的普通系统账号，以及固定的 Qwen2.5-1.5B-Instruct-Q4_K_M 模型。Linux 虚拟机分配 3 个 CPU 和 4 GiB 内存，宿主是 Apple Silicon；这不是 8GB 实体电脑、Mac 特权服务或 Windows/WorkBuddy 的验收。

| 检查 | 结果 |
| --- | --- |
| Agent 直接读取原件、保护区快照、恢复记录和未确认结果 | 系统拒绝 |
| Agent 自行修改原件权限或所有者 | 系统拒绝 |
| 伪造身份、通过公开接口选文件/解锁/导出/读取 | 拒绝 |
| 其他账号访问 Agent 接口 | 拒绝 |
| 虚构表格的筛选、排序、新增列、身份回填 | 与原始数据直接计算一致 |
| 虚构文档的未完成待办摘录 | 真实模型调用，原文逐字比对一致 |
| 同一原件再次处理、改名后取回快照 | 通过 |
| 符号链接、硬链接、命名管道 | 处理前拒绝 |
| 原件已被普通进程打开 | 停止，不声称保护生效，不读取原文 |
| 导出目标已存在 | 拒绝覆盖，已有文件保持不变 |

机器可读结果见 [kernel-isolation.json](verification/kernel-isolation.json)。此记录保留该次测试的源码指纹；后续平台测试另行记录，不能用早期指纹代表当前全部源码。

## Mac 临时机验证

GitHub 托管的 macOS 14.8.9 / ARM64 测试机运行了实际安装器、独立权限服务、固定本地模型与原有处理引擎：

- 自动下载及校验组件，真实自检 9 项通过，用时 21.585 秒；模型峰值内存 1.35 GiB。此指标不含下载时间，也不代表整机内存需求或 8GB 设备验收。
- 虚构表格 4 条筛出 3 条，合计 14，排序与新增列一致；虚构纪要摘取第 2、3、6 段，原文逐字一致。
- 普通 Agent 无法读取封存原件与未确认结果；确认后导出内容一致，原件仍受保护。
- 重复安装与服务重启通过，合格自检记录可复用。

选择文件和确认导出通过测试程序调用私有接口模拟，**没有验证真实窗口操作、WorkBuddy 或系统重启**。[原始核验记录](verification/macos-ci.json)。

## Windows 临时机验证

GitHub 托管的 Windows Server 2025 测试机已验证：普通账号在封存后不能读取原件或保护区快照，不能改变权限；原件已被其他程序打开时停止封存。通信使用操作系统提供的真实身份，普通账号无法进入私有接口，允许客户端另建服务实例的不安全权限配置被拒绝。

实际安装器使用包内 Python 注册 SYSTEM 服务，配置自动启动；普通账号无法读取私有配置或修改服务程序。就绪前的任务被拒绝，停止后重复安装可重新启动服务。这些结果不代表离线虚拟机任务、Windows 10/11 桌面、系统授权窗口或 WorkBuddy 已验收。[平台核验记录](verification/platform-ci.json)。

Windows 自动准备在 10 分钟观察期内未完成自检，保持不接收业务文件。GitHub 托管机器[不保证嵌套虚拟化的稳定性或兼容性](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners)，这次观察仍不能确定全部阻滞原因；Windows 离线环境需要在合适的可交互设备上继续验收。

## 自动安装开发验证

安装器选择操作系统和处理器架构，使用包内 Python；安装独立权限服务后，后台下载并校验固定模型，先运行虚构材料自检。后续复用服务和有效检查记录，不重装或复制 Agent 登录资料。临时资源不足可以再次查询重试，保护检查失败不启用业务处理。首次系统管理员授权不能由 Skill 绕过。

基础验证与源码指纹见 [Linux 和本地核验记录](verification/platform-installation.json)；后续平台结果见 [Windows/Mac 核验记录](verification/platform-ci.json)。受保护服务重启后已实测复用合格自检，原件与恢复记录仍拒绝普通 Agent 读取。Linux 与 Mac 的服务重启结果均不代表操作系统重启、真实桌面窗口或 WorkBuddy 已验收。

WorkBuddy 入口采用官方文档描述的兼容用户配置目录 `~/.codebuddy/skills`；仍需客户端发现与调用实测。[官方项目配置说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project)。
