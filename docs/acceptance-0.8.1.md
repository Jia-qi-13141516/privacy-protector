# 隐私保护 Skill 使用验收

2026 年 10 月 24 日 · macOS Apple Silicon · 仅使用虚构材料

**结论：未达到“交给 Agent 后自动完成、无需配置和切换窗口”的交付标准，不宜按该能力宣传或发布。**

## 实际完成了什么

- 从 0.8.0 压缩包重新解压并执行安装入口，确实出现功能选择窗口。根据本次反馈，0.8.1 已改为默认后台安装；旧向导按文件类型分流，不再询问表格或文档。已在本机实际安装并读取状态，未启动向导。Windows 的后台调用仅做控制流检查，没有实机证据。
- 表格底层：12 条虚构记录筛选为 8 条，姓名、编号、原业务数值与新增列逐项一致。独立复核用 18 条记录筛选为 6 条，同样一致。结果 CSV 由测试脚本按已知规则生成，**不是 AI 分析后的成功案例**。
- 文档底层：独立复核将虚构纪要整理为 3 项待办并回填人物代号，责任关系一致。待办由测试脚本构造，**不能据此证明模型摘要正确**。
- Mac 系统沙盒实际拒绝在线子进程读取选定原件、身份映射和实名导出；离线 worker 在禁止联网的环境处理原件。保护只覆盖新子进程，不隔离原聊天或整台电脑。
- 104 项自动化检查通过，其中界面路由与 Windows 衔接使用模拟适配器。这个数量不代表 104 次真实用户使用成功。

## 尚未通过的地方

| 问题 | 实测证据与影响 |
| --- | --- |
| 真实模型会话无法建立 | 表格与文档分别执行受保护 Codex 会话，均在启动阶段报 `Failed to synchronize managed preferences`。另外下载并校验官方独立 CLI 0.164.0 对照，仍失败。没有生成模型结果，尚未确定修复方案。 |
| 业务列的含义丢失 | “已报名次数”“待补材料数”在在线字段表都只保留“数值”；独立复核的两个业务字段也如此。模型无法仅凭用户原始任务可靠决定用哪一列。 |
| 普通人名漏检 | 虚构句子“林安负责联系周宁，陈禾负责向林安提交两份材料”在不填敏感词时替换数量为 0。独立复核也发现漏检姓名的稿件能通过确认。这种规则不能作为无需检查的通用文档脱敏。 |
| 零匹配不能正常交付 | 合法表头加零条结果被拒绝，无法正确完成“没有符合条件记录”的正常查询。 |
| 业务仍依赖向导 | 取消模式按钮和后台安装不等于后台处理；旧流程还有字段设置、文档检查及切换客户端。Mac 默认安装会退出，不是已经运行的持久任务服务。 |

## 验收范围

原生界面端到端未完成：测试工具不允许操控 Terminal，不能把模拟点击写成真实 UI 验收。真实账号的模型任务已尝试但启动失败；Windows、WorkBuddy 的实际双虚拟机任务未测。没有使用或上传真实学生资料，没有修改 GitHub 或飞书，也没有对外发布 0.8.1。

达到预期还需要：建立经过真实任务验证的后台执行通道；保留安全的业务字段含义并自动配置；使普通文档的本地身份识别达到可测、可说明的覆盖率；支持零匹配；最后完成老师视角与 Windows 实机验收。不能以关闭隔离、自动勾选人工确认或掩盖错误替代这些工作。
