# 隐私保护Skill

**你在使用 AI 时，有没有遇到过这些烦恼？**

- 想让 AI 帮忙处理表格，却因为里面有姓名、学号、联系方式，不敢直接上传？
- 花时间删掉了身份信息，拿到分析结果后，却又要逐条找回对应的人？
- 想把结果导入工作系统，还得反复核对：原来的数值有没有被改动，有没有重复记录？

**让 AI 处理表格，把身份信息留在本地。**

隐私保护Skill 为这类表格工作提供一套完整流程：**本地脱敏 → Agent 处理代号数据 → 本地核验与身份回填 → 确认后生成 Excel**。从需要保护的原表，到可以继续使用的结果，减少手工脱敏、身份匹配和格式核验的负担。

[下载安装包](https://github.com/Jiaqi-Guo-0114/privacy-assistant/releases/tag/v0.7.0) · [两种安装方式](#安装方式) · [支持范围](docs/compatibility.md)

## 解决什么问题

| 日常处理的难点 | 使用 Skill 后 |
| --- | --- |
| 原表含姓名、学号，不便直接交给 AI | 本地程序先移除未授权字段，用随机代号替换唯一编号；原表和身份对应关系留在本地。 |
| 脱敏后能分析，却难以恢复为可用名单 | 用任务代号衔接分析结果，在本地回填身份，支持只导出选中的记录。 |
| AI 改了原值、重复了记录，人工核对费力 | 导出前检查身份代号、原始数值、重复记录和新增列规则；不符合要求的结果会被拦截。 |
| 每次重新搭环境、反复找操作步骤 | 安装后保留运行环境，由 Skill 引导选表、处理与核对；首次授权和必要的账号登录仍需本人完成。 |

### 实际效果如何

| 本次虚构案例的检查 | 结果 |
| --- | --- |
| 脱敏前后的分数总和 | 均为 **1,644**，数值未改变 |
| 原表与代号表按同一规则筛选 | 均为 **21 条** |
| 导出记录的身份、分数和新增列 | **21 / 21 条**与预期一致 |
| 原表是否被改写 | 文件散列一致，原表未改变 |

这些结果说明：对于本例的数值筛选任务，脱敏后可以保留计算结果，并准确回填身份。**它不证明 AI 的分析判断永远正确，也不保证任意数据脱敏后都不影响结果。** 如果任务依赖被移除的文本、身份或细粒度分类，需要重新评估允许提供的字段。

项目现有 **69 项自动化检查通过**，覆盖安装包校验、访问边界、字段授权、结果篡改、筛选与新增列。当前为预发布版本：macOS Apple Silicon 的本地处理和访问拒绝已验证；Windows 完整流程、Mac Intel 与实际云端模型交互仍待验证。详见[兼容性与验证范围](docs/compatibility.md)。

## 安装方式

两种方式任选一种，安装的是同一个 Skill。

**方式一：压缩包**

下载 `privacy-assistant-0.7.0.zip`，交给电脑上能执行本地操作的 Agent，发送：

> 请安装并打开这个隐私保护Skill，根据我的系统配置运行环境。只读取安装包，原表由本地窗口选择。

若客户端不接受 ZIP，先解压，再让 Agent 读取其中的 `SKILL.md`。不要把安装 ZIP 当成普通文字上传到不具备本地执行能力的网页聊天。

**方式二：读取链接**

把下面这段话发送给本地 Agent：

> 请读取 https://github.com/Jiaqi-Guo-0114/privacy-assistant 的 SKILL.md，按说明下载、校验并安装隐私保护Skill，根据我的系统选择入口。不要读取我的业务原表。

首次系统授权和账号登录由本人完成。安装后保留运行环境和客户端账号资料；服务商要求重新认证时仍需本人登录。

## Windows 与 Mac

| 电脑 | 使用入口 |
| --- | --- |
| Windows x64 | 本地 WorkBuddy、Codex 或 Claude Code 发起安装；后台建立独立 WorkBuddy 环境。需要 Windows 10 2004 或更新版本、8 GB 内存、12 GB 可用空间和硬件虚拟化。 |
| macOS | 本地 Agent 发起安装，使用 Codex 或 Claude Code 命令行客户端。原生窗口完成选表和核对，新的受保护命令行窗口处理代号数据。需要 Python 3.9 或更新版本；依赖由 Agent 检查，表格库已在包内。 |

Mac 版支持本地脱敏、筛选、新增结果列及身份回填；不隔离 Mac WorkBuddy 的原有界面。首次安装按本机提示完成授权，检查失败就停止处理。

当前为预发布版本：Mac 本地处理与访问隔离已通过虚构表格测试；Windows 完整流程尚未实机验收。请先用虚构材料试用，具体范围见[兼容性说明](docs/compatibility.md)。

## 使用三步

1. **选文件**：在本地窗口选择原表，指定唯一编号和允许分析的字段。
2. **说任务**：在受保护的 Agent 窗口说明要统计或筛选什么，以及需要哪些结果。
3. **确认结果**：回到本地窗口，核对身份与结果，生成 Excel 文件。

例如：“筛选分数达到 30 的记录，新增是否跟进和 0—3 的优先级，生成导入表。不要改动原有数值。”

Windows 也可先在独立 WorkBuddy 中说任务，由它唤起选表窗口。Mac 会先选表，再打开新的命令行窗口；实名导出文件保存在受保护目录，完成后由访达显示位置。导入业务系统由本人完成。

## 工作原理

Skill 负责告诉 Agent **按什么步骤办事**；包内的本地程序负责 **真正读取原表、限制访问和核验结果**。仅靠一段“不要泄露”的提示词不能形成访问隔离。

```mermaid
flowchart LR
    A[本地选择原表] --> B[离线脱敏与核验]
    B --> C[允许提供的代号数据]
    C --> D[受保护的 Agent 分析]
    D --> E[本地校验结果]
    E --> F[本地回填身份]
    F --> G[本人确认并生成 Excel]
```

- **脱敏在模型接触数据之前完成。** 姓名等未授权字段被移除，唯一编号被替换为随机任务代号；分类字段也可替换为代号。原表、对应关系和密钥留在本地。
- **AI 只能处理本次允许提供的内容。** Windows 使用联网与离线的独立运行环境；Mac 使用禁止联网的处理进程，并限制新 Agent 进程读取私有目录和选中的原文件。两种系统的实现不同。
- **分析后再校验、回填。** 程序检查身份代号、原始数值、重复记录、筛选范围和新增列规则。结果通过后，才在本地恢复身份，供本人核对。

软件装在本机，不等于数据不会上传。Agent 使用云端模型时，**获准提供的代号数据仍可能发往模型服务商**。代号化不保证无法重识别，必须只选任务必需字段；不适合外发的内容应留在学校批准的环境内。

隔离只覆盖本 Skill 新启动的受保护会话，不涵盖原聊天窗口、其他软件、屏幕共享或主动上传行为。原表不要拖进聊天。

## 支持的表格任务

- XLSX 第一张工作表或 UTF-8 CSV。
- 数值统计、分类汇总、记录筛选。
- 新增“是否跟进”（yes/no）和“优先级”（0—3）。
- 本地回填身份，生成全部或选定记录的 Excel。

任意新增列、自由文本、公式和自动提交业务系统暂不支持。分类稀疏、编号重复、未知结构或结果篡改会停止处理。
