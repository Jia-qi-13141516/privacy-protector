# 隐私保护Skill

**用 AI 处理工作材料时，你是否也有这些顾虑？**

- 表格有姓名、学号和联系方式，不方便直接上传。
- 隐去身份后，处理结果难以对应回原来的记录。
- 工作纪要需要整理待办，但不适合交给云端模型。
- 电脑内存不大，也不熟悉模型和运行环境的配置。

**表格处理、文档摘录、自动自检，一套 Skill 在本地完成。**

从筛选材料台账，到整理纪要中的未完成事项：你负责说任务、选文件和核对结果，程序在后台完成支持的处理。表格由本地程序计算，文档由断网运行的本地模型摘录；此流程不把原件、代号稿或结果正文发给云端模型。

[下载 0.10.0 完整安装包](https://github.com/Jiaqi-Guo-0114/privacy-assistant/releases/download/v0.10.0/privacy-assistant-0.10.0.zip) · [版本说明](https://github.com/Jiaqi-Guo-0114/privacy-assistant/releases/tag/v0.10.0)

> **0.10.0 为公开测试版。** 已在 Apple M5、24GiB 内存的 Mac 上实测。**8GB 电脑、Windows / WorkBuddy 和 Intel Mac 尚未完成实机验收**，不能保证这些设备上的安装、速度和完整流程。

## 从一张台账，到一份纪要

| 日常场景 | 交给 Skill 的工作 | 得到的结果 |
| --- | --- | --- |
| 台账中找出需要跟进的记录 | 按明确数值条件筛选、排序、统计记录数及合计/均值，可新增统一跟进标记和优先级 | Excel，保留身份和原值 |
| 纪要中找出还没有完成的事 | 提取重要原文段落或未完成待办，保留原文中的负责人、交接对象和期限 | Word 和文本，便于逐项核对 |

**不熟悉配置，也能先用虚构材料试跑。** 首次安装自动检查电脑资源、运行保护与处理结果，通过才启用正式处理；任务自动排队。内存不足或保护检查失败会明确停止，无需老师选模型、调参数。

表格支持 XLSX 第一张工作表和 UTF-8 CSV；文档支持 TXT/MD、基础 DOCX 和纯文字 PDF。文档选段可能遗漏或误选，需核对结果。暂不支持任意改写、任意新增列、复杂公式、扫描件或自动提交业务系统。[详细范围](docs/documents.md)

## 安装：两种方式，任选一种

**方式一：交给 Agent 安装包。** 下载上方完整 ZIP，交给具有本地文件和程序执行能力的 Codex、Claude Code 或 WorkBuddy，说：

> 请安装这个隐私保护Skill，完成后台安装和虚构材料自检，告诉我是否通过。

**方式二：让 Agent 读取链接。** 直接发送：

> 请读取 https://github.com/Jiaqi-Guo-0114/privacy-assistant/blob/main/SKILL.md ，按说明下载、校验并安装隐私保护Skill，完成虚构材料自检。

首次需要下载约 **1.1GB** 模型。程序自动配置省内存参数、运行虚构材料自检；通过后才能处理正式材料。后续复用本地组件和合格记录，不要求重新登录 Agent。Windows 首次安装仍可能出现系统管理员授权或要求重启。

请下载 **privacy-assistant-0.10.0.zip**，不要选 GitHub 自动生成的 “Source code”。纯网页或云端 Agent 若没有本机执行通道，不能完成安装。

## 使用：说任务 → 选文件 → 查看结果

例如：

> 筛选待补材料数不低于3的记录，按待补材料数从大到小排列，新增是否跟进为需跟进、优先级统一为1。

> 把这份纪要整理为未完成待办，保留负责人、交接对象和期限，排除已完成事项。

提供本地路径，或在弹出的本地窗口选文件；完成后打开 Agent 返回的结果链接。**不要把真实原件直接上传聊天，也不要把姓名等敏感内容写进聊天任务。** 多个任务自动排队。内存不足、超时或保护检查失败时明确停止，不转云端、不放宽保护；关闭占内存的应用后可直接说“重试”。

## 原理

```mermaid
flowchart LR
    A[Agent转交任务] --> B[本地选择文件]
    B --> C[资源检查与断网保护]
    C --> D[表格计算 / 本地模型摘录]
    D --> E[本地核验与身份回填]
    E --> F[生成结果文件]
    F --> G[只向Agent返回状态与文件位置]
```

Mac 使用禁止联网的数据处理进程；Windows 代码通过无网卡的离线虚拟机处理。联网下载组件发生在业务文件处理之前。文档识别并非百分之百准确，但此流程不会把未识别的正文片段发送给云端。

保护只覆盖本 Skill 的处理流程，**不会撤销原 Agent 已有的文件权限，也不等于整台电脑被隔离**。标密材料不在支持范围内，单位的数据使用规定仍需遵守。

## 实测与设备要求

| 项目 | 已核验的情况 |
| --- | --- |
| 表格样例 | 8条虚构记录筛选出5条，降序及合计正确，身份、原值和新增列一致 |
| 文档样例 | 6段虚构纪要提取出3项未完成待办，保留责任关系与期限 |
| 首次自检 | 本次 Mac 上5.46秒、9项核验通过；复用已校验模型缓存，不含首次下载时间 |
| 自动化检查 | 151项通过；其中8GB和Windows资源边界使用模拟测试 |

**8GB是适配目标，不是最低配置已通过实测的承诺。** 短样例通过也不保证任意长文件均可完成。程序会自动检查资源，老师无需选择模型或调整参数。

- Apple Silicon Mac：macOS 13.3+、Python 3.9+；实际验收设备为 M5 / 24GiB。
- Windows x64：代码要求 Windows 10 2004+、8GB内存、12GB可用空间及硬件虚拟化；**尚未实机验收**，系统授权和单位策略不能绕过。
- Intel Mac：提供运行组件，**尚未实机验收**。
