# 隐私保护Skill 0.7.0 · 验证范围

本版已实现 Windows 自动下载安装、持久双环境、WorkBuddy 自动启动、后台任务衔接、本地确认与回填导出。不是只有提示词的 Skill；实际隔离依靠本地运行组件。

已完成：

- macOS 本地选表/字段设置/核对窗口与离线处理流程已接入。Apple Silicon 上，60 条虚构记录筛选为 21 条，身份、原值和新增结果准确回填；新进程拒读私有目录和选定原文件，拒改处理代码，未隔离处理与篡改结果被拒绝。Codex 命令行在边界内可启动。Intel 设备和真实云端模型交互尚未实测。

- 69 项自动化检查，包括完整安装包核验、重复安装、受控下载、权限边界、表格字段授权、篡改拦截、新增列和筛选导出。
- Ubuntu 24.04 中实际断网处理 60 条虚构记录，筛选 20 条，核对身份、数值与新增列准确回填；在有网络的环境中拒绝读取。
- 实际拒绝私有文件链接、管道文件、任意命令；修改防火墙后保护检查失败。
- 官方 WorkBuddy 5.6.2 的 Linux ARM64 包在独立 Ubuntu 环境实际显示登录界面。未登录真实账号，未复制任何凭据。
- VirtualBox 7.2.22 的 macOS ARM64 命令行实际检查网络、剪贴板、拖放、设备边界和启动介质操作；修正冷加载时回环访问设置恢复默认值的问题。
- Windows 安装/交互脚本完成 PowerShell 语法检查；cloud-init 初始化通过 Ubuntu 实际校验。

尚未完成 Windows x64 整机安装、UAC 交互、VirtualBox Guest Control 全链路以及真实账号重启后的登录保持测试。跨平台检查不等于 Windows 实机验收。程序在每台电脑首次安装时自动执行虚构表格、重启、私有目录拒读、身份回填和桌面可见性检查；通过前不会开放真实文件处理。这个自检用于阻止失败环境继续，不能代替尚未完成的 Windows 验收。

Windows 保护范围是自动打开的独立 WorkBuddy 会话；Mac 是新的 Codex / Claude Code 命令行进程及其子进程。主机上其他程序和原聊天窗口不会被追溯隔离；安装入口支持 WorkBuddy、Codex、Claude Code，不代表三个客户端的 Windows GUI 都已隔离。原表和身份映射只经本地主机与离线环境处理；模型收到用户授权的代号数据，不能因此称为不可重识别的匿名数据。

系统安装许可、第一次服务商登录和单位设备策略仍由本人/设备管理方决定。磁盘资料持久保存，不保证账号永不需要重新认证。程序不绕过操作系统或服务商权限，不自动向业务系统提交实名数据。
